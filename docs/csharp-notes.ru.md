# Заметки по C# и по решениям в этом проекте

Рабочий конспект: почему код написан так, а не иначе. README на английском —
он для пользователей; это — для нас.

## Настройки проекта, включённые осознанно

- **`<Nullable>enable</Nullable>`** — компилятор отслеживает, где значение
  может быть `null`. `string?` может быть null, `string` — нет, и обращение к
  возможному null становится ошибкой сборки. Главная защита C# от
  `NullReferenceException`. Включать надо сразу: потом это тысяча правок.
- **`<TreatWarningsAsErrors>true</TreatWarningsAsErrors>`** — предупреждение
  останавливает сборку. Жёстко, но иначе проект за год обрастает сотнями
  «неважных» варнингов, среди которых теряются важные. На этом коде анализаторы
  уже поймали три реальные вещи: `CA1859` (интерфейс в горячем аудио-пути
  мешает JIT девиртуализировать вызов), `CS8602` (лямбда читает поле до его
  присвоения) и `CA1001` (тип владеет освобождаемыми полями, но не объявляет
  `IDisposable`).
- **Central Package Management** — версия пакета задана один раз в
  `Directory.Packages.props`, в `.csproj` остаётся только имя. Иначе версии
  одного пакета в разных проектах разъезжаются, и ловится это уже в рантайме.
- **`<AllowUnsafeBlocks>`** включён только там, где есть interop с Win32:
  генератор `LibraryImport` пишет маршалинг с указателями. На остальные
  проекты флаг не расползается.

## Языковые конструкции, которые тут используются

- **`record` с `init`-свойствами** (`AppSettings`, `WhisperEngineOptions`) —
  объект собирается один раз и дальше неизменяем. Для настроек это то, что
  надо: никто не поменяет язык у движка из-под работающего распознавания.
  Изменённая копия делается через `with { ... }`.
- **`required`** — свойство обязано быть задано при создании объекта, иначе
  ошибка компиляции. По сути конструктор с обязательными параметрами, но
  по именам, а не по позиции.
- **Primary constructor** — `class WhisperEngine(WhisperEngineOptions options)`:
  параметр виден во всём теле класса, ручное поле не нужно.
- **`SemaphoreSlim` вместо `lock`** — там, где внутри критической секции есть
  `await`. Обычный `lock` удерживать через `await` нельзя, компилятор не
  разрешит. `WaitAsync(0)` даёт «занято — уходим», без ожидания в очереди.
- **`System.Threading.Lock`** (.NET 9+) — типобезопасная замена `lock (object)`:
  по объекту-замку нельзя случайно вызвать `Monitor.Enter` из чужого кода.
- **`LibraryImport` вместо `DllImport`** — генератор исходников пишет маршалинг
  на этапе компиляции: нет накладных расходов в рантайме, работает в native AOT.
  Требует `partial` у класса и методов.
- **Псевдонимы типов.** WinForms и WPF оба определяют `Application`,
  `Rectangle`, `Color`, а `ImplicitUsings` подключает оба пространства имён.
  Строка `using Application = System.Windows.Application;` снимает
  неоднозначность на весь файл.

## Архитектурные решения

**Логика отделена от интерфейса.** `TapRecorder.Core` не знает про WPF.
Это не абстрактная «слоёность»: именно поэтому весь пайплайн гоняется из
консольного харнесса, и именно так сделаны все замеры. `DictationController`
поднимает событие `TextReady`, а решение «вставить / положить в буфер /
напечатать» принимает вызывающий код.

**События приходят из фоновых потоков.** Контроллер, захват звука и слушатель
хоткея работают вне UI-потока. Единственное место, где события переводятся
в поток интерфейса, — `App.xaml.cs`, метод `OnUi`.

**Одно приложение вместо двух.** Диктовка и (в будущем) запись звонков живут
в одном процессе: общая модель на диске и в памяти, один трей, одни настройки.
Плюс исчезает целый класс багов — приложению не нужно отличать собственный
захват микрофона от чужого.

## Замеры, повлиявшие на архитектуру

На RTX 3060 12 ГБ и i5-9600KF, образец 28 с, `large-v3-turbo` f16:

| Бэкенд | Время | Скорость |
|---|---|---|
| CPU | 26,2 с | 1,1× реального времени |
| Vulkan, первый прогон | 12,6 с | 2,2× |
| Vulkan, прогретый | **0,52 с** | **53×** |

Выводы:

1. **CUDA Toolkit не нужен.** `ggml-cuda-whisper.dll` требует `cublas64_13.dll`,
   которого нет на машине без Toolkit (~3 ГБ), — Whisper.net молча откатывается
   на следующий рантайм. Vulkan идёт в составе драйвера GPU, даёт те же 53× и
   вдобавок работает на AMD и Intel.
2. **GPU обязательно прогревать на старте.** Vulkan компилирует шейдеры при
   первом использовании. Без прогрева первая диктовка после установки выглядела
   бы зависанием. У f16 и q8_0 ядра разные — каждая квантизация греется отдельно.
3. **`WhisperFactory.GetRuntimeInfo()` не показывает GPU-бэкенд** — только флаги
   инструкций процессора. Правду говорит `RuntimeOptions.LoadedLibrary`, и
   только после загрузки модели. На этом легко полгода думать, что работает GPU.
4. **Промпт — якорь стиля, а не только словарь.** `large-v3-turbo` без промпта
   пишет без пунктуации и заглавных, цифрами: `1 2 3 4 5 алло алло`. С промптом
   на том же файле сразу расставляет знаки препинания.
5. **Нерелевантный промпт вредит.** Промпт про таск-трекер на записи со счётом
   до десяти замедлил `large-v3-turbo` вчетверо — декодер терял уверенность и
   уходил в temperature fallback.

## Пойманные баги — и что из них следует

**Зомби-процесс, державший хоткей.** Консольный харнесс слушал только `Ctrl+C`.
Закрытие окна консоли — это `CTRL_CLOSE_EVENT`, который .NET показывает как
`SIGTERM`, и `Console.CancelKeyPress` на него не срабатывает. Процесс пережил
своё окно и продолжал держать глобальный хоткей: приложение потом не могло его
занять, а пользователь видел «горячая клавиша занята» без видимого виновника.
Отсюда два следствия: подписка на `PosixSignalRegistration`, и пункт меню
«Занять горячую клавишу заново» — конфликт возникает при старте, а разрешается
позже, и требовать ради этого перезапуск фоновой утилиты неправильно.

**Разбор аргументов.** Флаги отфильтровали из позиционных аргументов, а их
значения — нет. Текст промпта уехал в параметр «путь к файлу». Мораль: парсер
обязан знать, после каких флагов идёт значение.

**Позиция окна при масштабе экрана.** Позиция вычислялась до первого `Show()`,
когда у окна ещё нет HWND. `PresentationSource.FromVisual()` вернул `null`,
`?? Matrix.Identity` превратил это в масштаб 1, и пилюля уехала вправо.
На 100% масштаба баг невидим — проявляется только при 125/150%.

Общий урок из последнего: `?? default` и `?.` удобны, но превращают «данных ещё
нет» в правдоподобное неверное значение. Там, где падение честнее молчаливого
дефолта, лучше падать. Лечится либо ранним созданием HWND
(`WindowInteropHelper.EnsureHandle()`), либо API, который не врёт молча
(`VisualTreeHelper.GetDpi()`).
