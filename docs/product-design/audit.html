What mixed speech actually requires

Fast sequential turns: the current whole-segment winner loses the second speaker. Keep diarization intervals, obtain word timing and split text at a supported boundary. CTC forced alignment and native whisper.cpp token/DTW timing are candidates to compare; native timestamps are explicitly experimental. Do not choose a new stack before checking the current C# wrapper, Russian/mixed-language accuracy, memory and CPU/GPU behavior.

Actual simultaneous speech: preserve concurrent speaker intervals and allow simultaneous editable segments. Diarization indicates who was active; it does not guarantee recovery of both voices' words from one mixed system track. Flag uncertainty, support direct manual repair, and investigate targeted separation/retranscription only after documenting what text is missing. Keep microphone/system tracks distinct. A waveform or an exclusive single-speaker timeline cannot recover lost words.

Important loss in the current pipeline: diarization spans are used to pick one Voice and are not retained in the transcript. Verification works on entire lines, skips lines under four seconds and can automatically move a line to another voice. This cannot reliably diagnose the short interruption that matters most to you.

Research basis: WhisperX word alignment research, whisper.cpp experimental token/DTW timestamps, and pyannote regular/exclusive diarization. These establish possible techniques, not proven drop-in compatibility or local performance for this project.

Proposed interaction model

Use the discipline of professional editors: clear selection scope, a separate playback cursor, discoverable commands and reversible edits. Reproduce those behaviors rather than the density of a full video-editing workstation.

Hide when not useful.

  • Caret / selection: edits apply locally. A selected span is the explicit scope for correction, assignment and deletion. A bulk replace preview lists occurrences; dictionary learning is a separate opt-in action. Enter performs local correction.
  • Split: divide at a caret/word boundary; choose or adjust the audio boundary if timing is unavailable. Do not infer precise time from character position. Support merge and inserting a missing segment with a chosen interval.
  • Speaker: assign any existing person or create one, without rerunning diarization. Identity and source channel are independent. Manual choices are locked against background inference until explicitly cleared.
  • Undo: toolbar and Ctrl+Z/Ctrl+Y, with a visible operation name. One bulk correction is one transaction. Undo speech edits must not quietly alter dictionary settings in another domain.
  • Playback: timestamp seeks; an explicit range/segment action plays a bounded excerpt. Play/Pause resumes the exact playhead. During editing, follow can be disabled. An optional speed control follows once transport behavior is stable.

Menu and export scope

Library row menu: Rename, Export, Show in folder; then Processing (Transcribe/Retry/Retranscribe); Delete separated last. Context menus and ellipsis expose the same commands and correct clicked item. Retranscription preserves or creates a recoverable revision of manual edits.

Header: primary controls are Play/Pause, Undo/Redo and Export. Overflow holds call management and processing actions: Rename, Show in folder (unless still a visible header action), Retranscribe, Recompute speakers and Delete. Hide inapplicable operations; explain temporarily disabled operations. Move privacy options and Open transcript to the delivery/file domain.

Export: Copy to clipboard and Save as. Start with TXT, existing Markdown, versioned JSON; SRT/VTT follow once subtitle timing/reflow policies pass. Options control speaker labels, timestamps, real names versus aliases and selected range versus whole call. Add DOCX/PDF only with a defined readable layout and visual QA. HTML and audio export remain deferred.

Right-pane decision

Separate manual People management from machine assistance. Keep the former; require evidence for the latter. The default editor must work with the inspector closed and voice recognition disabled. A review queue should show a concrete problem and a direct repair action, not a stack of guesses the user must curate.

Evaluate on real calls using correction time, accepted/useful suggestions, false flags, missed short interruptions and management clicks. No numeric target is claimed before measuring a baseline. If suggestions cannot show a net improvement, remove them from the default workflow. An offline local model with a newer model card is a candidate for a bounded experiment, not an automatic replacement for the current Sherpa/ONNX pipeline.

Proposed implementation order and release gates

Phase 0 · Starts immediately; no model commitment.

Establish real failure cases

Record a small labeled corpus from representative calls: rapid sequential turns, short yes/no interruptions, mic/system overlaps, multiple remote speakers, silence, noisy speech and similar voices. Capture the current Windows interaction failures. Keep fixtures private and anonymized when feasible.

Exit gate: Baseline correction time, missed words, speaker errors, overlap flags, latency and peak memory. Evaluate both specified PCs; memory/GPU results are not interchangeable.

Phase 1 · First implementation tranche.

Make the current app safe

F01–F06, F13; F07 unsafe defaults. Coordinate jobs/settings, cancellation/commit, silence padding and microphone loss. Remove default dictionary/similar-form selection. Introduce basic recoverable snapshots before broad editing operations.

Exit gate: Focused lifecycle and storage tests; first-click menu tests; live device-loss/settings/cancel checks. No cancelled job reports success or commits late.

Phase 2 · Architecture/design review before implementation.

Build a reversible transcript editor

F07, F14, F21. Stable IDs, revisions, human locks, command Undo/Redo, local text edit, selected-range assignment, split/merge and missing-segment insertion. Timing can initially be set/adjusted manually with an explicit time selector; text selection alone does not imply audio timing.

Exit gate: One interruption can be repaired and undone without full retranscription. All edits preserve unrelated content; restart and background jobs retain human changes.

Phase 3 · Can follow editor foundation; no workspace rewrite.

Make finding and delivering calls coherent

F08, F18, F19, F20. Row menus, People/date/status filters, off-thread library work, unified header and Export. Begin with text/Markdown/JSON; add subtitles when cue policy and timing are verified.

Exit gate: Large real library remains responsive; exports match edited state and privacy options; actions use the correct selected/clicked call.

Phase 4 · Timeline display does not require a new ASR engine; fine-grained automation does require timing.

Add accurate audio navigation and automatic boundary repair

F12, F15, F16. Transport controls and simple seek first; cached two-track waveform/range selection next; word timing and speaker lanes after validated alignment. Run a bounded alignment/diarization spike alongside earlier design, with no shipping model switch until measured.

Exit gate: Representative Russian/mixed-language calls show less correction work. Seeking and audio/text highlighting stay consistent. Uncertain/mixed regions remain visible and repairable.

Phase 5 · Explicit go/no-go decision, no invented numeric quality claim.

Keep or remove assistance based on results

F17. Optional People / Review inspector. Compare it with direct editing on the same class of calls. Exclude short or mixed samples from identity learning unless their quality is established.

Exit gate: Suggestion usefulness and time saved exceed false suggestions and management overhead. Otherwise remove inference assistance from the default UI, keep manual People controls.

Decisions still open: whether DOCX/PDF belongs in the first Export release; simple seek versus waveform in the first navigation release; whether helper suggestions survive the usefulness test; whether a model change wins a measured comparison. The recommended core commitment is safe edits + manual partial-speaker repair + reliable jobs.

F01 · FIX · Original audit

P1 · Reliability

1. Changing settings can abort a call transcript

Changing model, language, VAD, normalization or beam settings launches a rebuild. Rebuild disposes the shared engine/detector while an active call retains its old transcriber. A subsequent speech region or second channel can fail.

Evidence: App.xaml.cs:1987,2103
Control-flow finding; not reproduced with live audio.

Better path: Coordinate engine replacement with running jobs; defer changes or cancel and settle explicitly.

F02 · FIX · Original audit

P1 · Reliability

2. Cancel can still overwrite a transcript

Final verification and voiceprint callbacks run synchronously inside Task.Run. Its token prevents scheduling but does not interrupt a running callback. The final Store has no cancellation check. Cancellation in the final pass can therefore still commit, particularly with RememberVoices disabled or during the last voiceprint pass.

Evidence: CallTranscriber.cs:188,431,505
Control-flow finding; timing-dependent.

Better path: Check cancellation inside embedding loops and immediately before committing.

F03 · FIX · Original audit

P2 · Reliability

3. Long silence moves system speech to the wrong time

Each silence padding operation is capped at ten minutes. A valid twenty-minute loopback gap writes the first returning packet near minute ten, then later packets insert catch-up silence. A silent tail over ten minutes can leave the track too short.

Evidence: TimelineWavWriter.cs:194
Deterministic arithmetic in writer; hardware reproduction not performed.

Better path: Validate reference clocks separately and preserve full legitimate gaps.

F04 · FIX · Original audit

P2 · Reliability

4. Settings rebuild races dictation cleanup

DisposeAsync resets and disposes the semaphore before awaiting an in-flight ToggleAsync. That operation later releases the disposed semaphore; old controller events can also arrive after replacement.

Evidence: DictationController.cs:162,461
Control-flow finding; timing-dependent.

Better path: Track the active operation, cancel it, await settlement, then dispose.

F05 · FIX · Original audit

P2 · Reliability

5. Lost microphone still appears to record

OnCaptureFailed publishes a notice but leaves the recording state, capture reference and duration fuse running. The user can keep speaking into a capture that has failed.

Evidence: DictationController.cs:278
Control-flow finding; device-unplug test still needed.

Better path: Stop capture and transition to an explicit error/recovery state; preserve collected speech.

F06 · FIX · Original audit

P2 · Responsiveness

6. Initial call processing runs on the UI thread

The dispatcher invokes transcription directly. Before the first yielding await, it synchronously reads the full microphone WAV, builds its energy envelope and normalizes audio. ConfigureAwait(false) only affects later continuations. Long calls can block the window and delay Cancel.

Evidence: CallTranscriber.cs:135,562; App.xaml.cs:1453
Thread-flow finding; freeze duration not measured.

Better path: Move file decoding and preprocessing to cancellable background work.

F07 · REWORK · Original audit

High · Correction workflow

7. A small correction defaults to a broad permanent change

Similar forms start selected; Remember starts enabled; Enter executes ReplaceEverywhere. The transcript is overwritten without persisted edit history. A context-specific correction can alter a whole call and future dictations.

Evidence: CallsPage.WordFix.cs:110,123,229; CallTranscript.cs:216
Verified defaults and persistence; usability assessment.

Better path: Make local correction the primary Enter action. Offer explicit bulk scope and opt-in dictionary learning, with undo.

Expanded by daily-use feedback: default both dictionary learning and similar forms off; local selection correction is primary; add Undo/Redo in the toolbar and shortcuts. Persist recoverable revisions before exposing split/merge. Details: F14 and F21.
F08 · FIX · Original audit

Medium · Scale

8. Call history repeatedly performs disk work on the UI thread

Every two seconds the dispatcher scans all call folders and loads metadata. Search reads uncached transcript files synchronously as filters run. Existing caching helps repeated search but does not remove the repeated metadata scan.

Evidence: CallsPage.xaml.cs:55,218,441; CallLibrary.cs:89
Structural scale risk; no large-library benchmark.

Better path: Refresh changed entries incrementally; load and search off-thread.

F09 · REWORK · Original audit

Medium · Product scope

9. Three workflows have accumulated without a single dominant task

Dictation, call recording/review, and dictionary/voice management share one product. Call work exposes participant hints, unnamed voices, reassignment, word-form correction, verification and sharing. These are useful capabilities, but the default path leaves the operator managing recognition internals.

Evidence: MainWindow.xaml:92; CallsPage.Transcript.cs; SettingsWindow.xaml.cs:294
Product inference from implemented flows; user observation needed.

Better path: Choose the dominant task. For calls: Record, read, review flagged issues, export. Keep model tuning and identity maintenance secondary.

Re-scoped: this is a mature daily-use app. Preserve dictation and the successful visual foundation. Prioritize call review as the primary improvement area; the earlier broad product-scope interpretation remains a hypothesis, not a reason to remove useful features.
F10 · DEFER · Original audit

Medium · Scope gap

10. Existing recordings have no normal import workflow

The UI file picker imports dictionaries; calls originate in the dual-track recorder. Core can decode audio, but there is no normal audio/video file import action in the reviewed UI. This matters if transcribing existing recordings is a core expectation.

Evidence: DictionaryPage.cs:781; CallsPage.Sharing.cs:25; AudioFile.cs:16
Repository-wide UI search; requirement-dependent.

Better path: If file transcription is a real need, add a dedicated import flow rather than forcing external recordings into call folders.

Deferred: existing-file import was an audit suggestion, not a requested pain point. It does not belong in the first fix tranche.
F11 · FIX · Original audit

Medium · Memory

11. Whole-track arrays amplify long-call memory usage

At 16 kHz float32, one hour is about 220 MiB per array. Reading creates a List and a copied array; normalization may create another full array. Four-hour tracks are about 879 MiB per array. Sequential channel processing helps, but peak memory remains much larger than the WAV size.

Evidence: AudioFile.cs:36; SpeechTranscriber.cs:72; AudioNormalizer.cs:68
Calculated allocation scale, not measured process working set.

Better path: Prefer bounded chunks; at minimum normalize owned buffers in place and avoid List-to-array duplication.

F12 · REWORK · Critical editor limitation

Mixed speakers are collapsed into one segment label

User-observed; structural cause confirmed

SpeakerAssignment sums overlap per speaker and chooses one winner for the entire ASR segment. The transcript keeps one Voice, no word timings or retained speaker-span list. Thus close sequential turns can be mislabeled even when diarization finds their boundary. True simultaneous speech is a separate case: two voices in one system mix may also mean ASR omitted or merged words. A later whole-line voice check cannot restore missing words.

Proposed change: Retain diarization intervals and overlap flags; introduce word timing/alignment and split sequential turns at supported word boundaries. Support simultaneous segments instead of forcing exclusivity. Allow manual split/assignment immediately through an explicit time-boundary workflow. Prototype targeted local retranscription or separation only for difficult overlapping excerpts; do not promise a model swap fixes mixed audio.

Done when: Fixtures distinguish fast turn-taking, mic/system overlap, and two simultaneous remote speakers. Missing content is flagged; unsupported word boundaries are approximate and adjustable. No character-count timing masquerades as measured alignment.

Code evidence

SpeakerAssignment.cs:For; CallTranscript.cs:CallLine / CallVoices.Assign; CallTranscriber.cs:SplitAsync; WhisperEngine.cs:202

F13 · FIX · Immediate

Transcript context menu needs a second right-click

User-observed; implementation matches documented WPF timing problem

The handler replaces TextBox.ContextMenu only while ContextMenuOpening is already firing. There is no preexisting custom menu in the template. Microsoft documents the exact first-click failure when a newly assigned menu arrives too late.

Proposed change: Initialize a menu ahead of opening or explicitly handle and open it with a reentrancy guard. Preserve the selected text and target under the pointer; support the context-menu key and Shift+F10. Test recycled WPF rows, not just freshly created controls.

Done when: First right-click and first keyboard invocation open the correct menu on a fresh or virtualized row without changing selection.

F14 · REWORK · Core product work

Editing needs a selection-based command model

User-observed; current line-level restriction confirmed

Text correction, full-line editing, speaker reassignment and playback use separate gestures. Selected text can be corrected or copied, but assignment and deletion target the whole line. With no diarized voices, assignment becomes 'split voices', which substitutes an expensive inference operation for a manual edit. The microphone channel is also treated as identity by construction, so correction cannot generally override it.

Proposed change: One predictable edit flow: caret edits text; a selection exposes Correct, Delete, Assign speaker, Split at caret, Play selection, and optional Replace occurrences. Provide Merge adjacent segments and Add segment for omitted speech. Assignment must accept a new named person without rerunning diarization. Preserve source channel separately from human speaker identity. Advanced operations use the same commands in toolbar, shortcuts and context menus.

Done when: The user can isolate half a sentence, assign it to an existing or new person, add missing text, merge a mistaken break and undo everything without retranscribing the whole call. No gesture unpredictably changes correction scope.

Code evidence

CallsPage.Transcript.cs:LineMenu / ReassignLine / DeleteLine; CallsPage.WordFix.cs:EditLineInPlace; TranscriptEdit.cs

F15 · ADD · Stage in two releases

Playback has no precise navigation or range workflow

User-observed; timestamp behavior confirmed

Timestamp click plays from the segment start to the end of the call, rather than a bounded excerpt. Stop/resume uses the current line's start rather than an exact preserved playback position. There is no visible scrubber/range selection in the reviewed UI.

Proposed change: First add clear Play/Pause with exact resume, elapsed/total time, seek, previous/next segment, short rewind, play a bounded selection and a follow-transcript toggle. Then add a collapsible two-track waveform with min/max peak cache, zoom, range selection and speaker intervals. Keep time navigation out of the compact title/action header; use a transport strip near the transcript.

Done when: Users can compare a short disputed exchange repeatedly without replaying the rest of the call. Seeking, text selection and playhead are distinct; every transport control has a keyboard path.

Code evidence

CallsPage.Playback.cs:OnStampClick / PlayFrom; Audio/CallPlayer.cs:Play

F16 · REWORK · Immediate simplification; precise version after alignment

Playback sweep does not represent spoken text

User-observed; rendering and clock limitations confirmed

Progress is calculated from segment duration, then scaled across the entire row. It does not map elapsed audio to words or wrapped text. A 100 ms dispatcher timer makes visible steps, and the clock uses the reader position ahead of heard output by buffering. FollowPlayback picks the latest segment start without checking segment end and tracks only one current row, so gaps/overlap are poorly represented.

Proposed change: Remove the misleading row-width sweep now; retain a subtle active-segment indicator. Separate playback clock, selection and review state. After word alignment, highlight words using measured timing and actual text layout, with render-time interpolation from the audio clock. Edited or inserted words with no timing remain visibly unaligned; gaps highlight nothing, overlaps can highlight multiple segments.

Done when: No sweep into blank row space; no line falsely active throughout silence. Multiline text, seeks, pauses, playback speed and overlapping segments display consistently.

Code evidence

CallsPage.xaml:Sweep / ScaleTransform; CallsPage.xaml.cs:110; CallsPage.Playback.cs:FollowPlayback; Audio/CallPlayer.cs:Position

F17 · REWORK · Decision gate

Voice helper must earn its screen space

User-reported friction; utility not measured

The current panel occupies a substantial fixed-width column and combines identity, samples, suggestions and voice repair. Verification skips lines shorter than four seconds; unmeasured lines have no doubt badge. A mixed-speaker line can contaminate examples or embeddings, so apparent confidence is not proof of correctness.

Proposed change: Replace the permanent sidebar with an optional People / Review inspector. People manages identities explicitly. Review shows actionable items such as mixed speakers, unassigned spans or contradictory evidence with play/jump and concrete corrections. Move speech-share statistics out of the correction path. Keep local voice recognition optional and never treat its score as a calibrated probability.

Done when: Measure assisted versus manual correction time, useful suggestion rate, false flags, missed short interruptions and extra clicks on representative real calls. Keep suggestion features only if they reduce net effort. Otherwise remove them from the default flow while retaining manual speaker management.

F19 · ADD · Core delivery workflow

Export should unify clipboard, files and privacy settings

User-requested; current UI primarily copies or opens Markdown

Copy and anonymized copy are separated from file delivery. The reference lists TXT, SRT, VTT, HTML, PDF, JSON and DOCX; implementing every format immediately would dilute attention from trustworthy edits and timing.

Proposed change: Use an Export dropdown with Copy to clipboard and Save as. Initial formats: TXT, Markdown (preserve existing output), SRT/VTT, versioned JSON. F21 · REWORK · Before split/overlap editor

Stable identity and provenance are prerequisites for serious editing

Confirmed data-model constraint; new design work required

Lines are identified by channel plus start time. Splitting, boundary moves and same-channel overlaps can invalidate that identity or create collisions. Human assignment is expressed by clearing Fit; it is not an explicit lock/provenance field. A later verifier can recalculate and move the line. Persisted files hold current state rather than a durable reversible command history.

Proposed change: Version the document schema with stable segment IDs, source references, optional word timing and explicit human/machine/unknown provenance. Preserve original recognition output alongside editable state. Introduce reversible edit transactions and checkpointed persistence; group a bulk edit into one undo step. Background analysis operates on a revision and cannot overwrite newer edits or human-locked speaker assignments. Keep dictionary changes in their own explicit undo scope. Migrate old calls once and preserve rollback/backups.

Done when: Old recordings remain readable; splitting never edits another segment with the same timestamp. Undo/Redo works after selection changes and restores text, timing and speaker state coherently. Restart restores saved edits; background analysis cannot overwrite them. Retranscription creates a recoverable new revision rather than destroying manual work.
